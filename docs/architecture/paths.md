# Paths

Covers `paths/`, the pathfinder lock and the path editor. The rules that apply everywhere are in [CLAUDE.md](../../CLAUDE.md).

Experimental. A path is a list of PSN-absolute X/Y/Z points a marker can be locked onto and walked along.

- **`paths/geometry.py`**: `build_curve` turns a path into a `PathCurve`, straight between its points with each interior corner (every corner when closed) rounded by an arc of that point's radius. An arc takes at most half of either neighbouring segment, so a radius too big for the corner shrinks; a turn of 180° stays sharp. The curve is a dense polyline whose chords stay within 1 mm of the arcs, addressed by arc length `s`: `point`, `tangent`, `nearest`, `advance` (an open curve reports which end stopped it), `offset` (the shorter way round a loop). Z follows linearly along the straight parts and through each arc.
- **`paths/network.py`**: `PathNetwork` holds the active paths' curves and their junctions. Two paths meet where they cross in plan at the same height (`JUNCTION_HEIGHT_M`, 0.1 m), and a path whose end lies within `JUNCTION_REACH_M` (0.1 m) of another joins it there. A path crossing itself, or a loop coming close without crossing, makes no junction. `walk` moves a locked marker by the part of the push that points along its path; at a junction it takes the direction closest to the push, leaving its own path only when the other is `_SWITCH_MARGIN_RAD` (15°) closer. A marker within `_CAPTURE_M` of a junction can steer into it from standing. Pushing past an open end stops there, or reports `released` when that end releases. `glide` travels a fraction of the shortest route through junctions (the mouse), `nearest` and `connected` answer where a position projects.
- **Names** are what OSC addresses: `[A-Za-z0-9._-]`, at most 32, unique ignoring case. `PathsConfig.__post_init__` reduces a bad name and renames a clash (`-2`, `-3`) rather than dropping geometry; caps are `MAX_PATHS` (32) and `MAX_PATH_POINTS` (100).
- **Active is per station.** `PathsConfig.replace_paths` takes another source's paths but keeps this station's Active flag per name (a new name arrives inactive); every route that writes paths from outside uses it: the `paths` section of the JSON API and section broadcast, import and Broadcast All (which carry paths, unlike zones), and the `paths` template type. `show_paths` is device-local in the section (`_DEVICE_LOCAL_FIELDS_BY_SECTION`). A `paths` value that is not a list leaves the paths alone.
- **`paths/engine.py`**: `PathEngine` (`app._paths`, rebuilt by `reload` whenever `[paths]` changes or the experimental switch flips; with it off nothing is active, nobody stays locked and nothing records) holds each locked marker's place, in memory only. A Pathfinder press (`press`) pulls an unlocked marker onto the nearest active path over `slide_time`: its input keeps moving a free position, and what is written is eased from that position to the nearest point of the path, so the marker carries on and lands where its movement took it; a second press, Reset, deactivating the path or deleting it releases. An edit to the path puts the marker back on the edited curve, written by the next `tick`. **Every movement source asks the engine before writing a locked marker and writes what it answers**, so no output ever carries a position off the path: relative input through `InputManager._move` (`move`, Z inputs ignored, height is the path's), the 2D mouse through `glide`, OSC positions and the Fully Automatic pin through `project` (nearest reachable point); AI Assisted constrains the operator's anchor, which is what input drives. `tick` runs at the top of `InputManager.update`, after locks of markers no longer controlled are released.
- **`runtime/paths_runtime.py`** is the frame-loop glue: Pathfinder presses (`InputManager.pathfinder` from the keyboard's selected marker, per pad as `GamepadUpdate.pathfinder_presses`, per puck), recording (a press while `engine.recording` appends the steered marker's X/Y/Z and saves), Toggle paths (`show_paths`, saved), OSC commands, and the blue `path_recording` status row. The bindings (`btn_pathfinder`, `btn_toggle_paths`, `key_pathfinder`, `key_toggle_paths`, `mouse3d.btn_pathfinder` / `btn_toggle_paths`) start unbound, sit last in their form groups, and their form rows carry `experimental-feature`; the help overlay names them only while paths run.
- **OSC** (`osc/paths.py`, subscribed while the OSC listener is up): `/path/<name>/active <on>` switches a path (saved), `/marker/<id>/path <name>` locks a controlled marker onto an active path, no name releases. Queued and applied on the frame loop; ignored while experimental features are off.
- **Operator Screen**: active paths (and the one recording) are drawn by `overlay_draw_paths` after zones, grey and semi-transparent, opaque white while a marker is on one (`COLOR_PATH` / `COLOR_PATH_LOCKED`), with a dot on each point; the drawn line is the curve with straight runs split every 0.25 m so the lens bows it. `PathCache` keeps every path, grey, as one picture and the paths with a marker on them, white, as a second picture over it: a marker crossing a junction redraws only the second. Each is drawn again when a curve, an end, the camera, the lens, the frame size or the device scale changes; a curve is the engine's own list until the paths reload, so the key compares by identity.
- **Turning experimental features off deactivates every path** (`/settings/experimental`), as it turns detection off.
