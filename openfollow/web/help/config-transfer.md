# Configuration

Move a station's full settings in and out as a single `.ofsettings` file – duplicate a config across stations, archive a rig before changes, or recover from a snapshot – put every setting back to its default, or bring back one of the backups the station saved before a change.

**Export Configuration** – downloads the current configuration as a `.ofsettings` file containing every saved setting (camera, grid, markers, zones, OSC, MIDI, input, display).

**Import Configuration…** – opens a file picker for a `.ofsettings` file exported from any OpenFollow station; files ending `.openfollowsettings`, from earlier versions, import the same way. Choosing a file asks first, naming it, and nothing is applied until **Import** is pressed. A backup of the current settings is then saved on the station, and every show setting is replaced, the station name, marker selection, detection masks and the remembered video sources included, and takes effect straight away; the page reloads and confirms which file it imported. The automatic update check and clock sync, whether pre-releases are offered, where updates come from and the network backend are read when OpenFollow starts, so an import changes them from the next start. What stays is what connects this box rather than describes the show: the web login PIN, port and interface, the station's identity, its interface pins and labels, and local file paths such as the detection model storage. The per-marker move speeds also stay as they are.

When the station's settings file could not be read, every save is refused until it is replaced, and an import or the restore of a backup is what replaces it; what connects this box is kept from the settings it last read. A settings file that is empty is restored from its backup copy when OpenFollow restarts, or started again with default settings when there is none.

**Restore Defaults** – returns every setting to the value a fresh install has: camera, grid, markers, zones, OSC, MIDI, input, display and video source. A confirmation dialogue appears first, then a backup of the current settings is saved on the station. The station restarts to finish the reset – a few settings only take effect at startup – and the page returns on its own once it is back. It is refused while a software update is running. What stays is what describes this box rather than the show: the web login PIN, port and interface – network access is not reset, so this page keeps working – the station's identity (its name follows that identity, as it did on the first run), and local file paths such as the detection model storage. Marker definitions in the shared catalog and uploaded media are not settings, so they are untouched.

**Backups on this station** – the station saves its settings before every software update and before every import, restore to defaults, restore of a backup and push of settings from another station. A backup holds the configuration, the marker catalog, the saved templates and the saved lens calibrations; the Media Gallery and the detection models are not in it. The station keeps the ten newest taken before an update in its `backups` folder and, apart from those, the ten newest taken before a change in the web UI in `backups/web`. When none could be made, the change still goes ahead, and its confirmation turns orange and says so; the station's log holds the reason.

The list shows them all, newest first: when each was made, in this browser's time, what it was made before, and the version of OpenFollow that wrote it. **Restore…** asks first, naming the backup, and nothing changes until **Restore and Restart** is pressed. A backup of the current settings is then saved, the backup's configuration, marker catalog, saved templates and lens calibrations replace the current ones, and the station restarts; the page returns on its own once it is back. A part the backup does not hold, such as the lens calibrations of a backup made before they were saved, stays as it is. What stays as well is what describes this box rather than the show: the station name, the web login PIN, port and interface, the network mode and station interface, the station's identity, and local file paths such as the detection model storage and where the marker catalog is kept. After the restart the marker catalog is shared with the other stations again as usual, so a marker another station changed or deleted since the backup follows that station. A backup made by a newer version of OpenFollow than this station runs cannot be restored: its row says so. A restore is refused while a software update is running, and a backup that does not read is refused with that reason and changes nothing. A backup never leaves the station: it holds the web PIN and stream passwords, so it is never exported or sent to another station.

**Pushed settings** – when another station sends its settings here (**Apply to all stations** on its Grid or Camera page, or a script using its configuration API), every page of this station's web UI shows a dialogue that stays until **Remove Warning** is pressed. It lists each push since the warning was last removed, newest first: the station clock's time, the sending station's name and address, and what it sent. A push of **every shared setting** carries the whole configuration except what each station keeps for itself: OSC destinations and transmitters, trigger zones, interface pins and labels, the login and the station name, and what describes its own setup: its marker selection, detection masks, the video sources it is not showing, 3D Mouse, operator messages, MIDI patches, virtual faders, gamepad mapping, whether it draws paths, whether it offers pre-releases, its automatic update check and clock sync, and its network backend. The Operator Screen shows the newest push as a blue row in its status corner, and while one is pending its Settings menu lists **Remove Pushed Settings Warning** first. The settings are already applied when the warning appears; removing it, from any browser or the Operator Screen, only acknowledges them, everywhere at once, and each open page reloads to show the values pushed. A push never renames this station: it keeps its own name, which only an imported file replaces. A restart of OpenFollow clears the list. From a station on 0.5.0-rc1 or earlier, a push of every shared setting raises it under the sender's address alone, and a push of one page raises nothing.
